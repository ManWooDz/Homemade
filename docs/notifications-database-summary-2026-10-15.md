# ฐานข้อมูลที่เพิ่มสำหรับการแจ้งเตือน

เพิ่มตาราง `notifications` หนึ่งตารางใน PostgreSQL เพื่อเก็บประวัติและสถานะอ่านตามบัญชี เมื่อเปิดหรือกลับเข้าแอปบนอุปกรณ์อื่นจะดึงสถานะล่าสุดจากเซิร์ฟเวอร์ ไม่ได้ส่งแบบ realtime ตลอดเวลา

| คอลัมน์ | ชนิด | ความหมาย |
|---|---|---|
| `id` | Integer, Primary Key | รหัสแจ้งเตือน ใช้เรียงรายการและแบ่งหน้า |
| `user_id` | Integer, Foreign Key → `users.id` | เจ้าของแจ้งเตือน จำกัดสิทธิ์ตามบัญชี |
| `kind` | Varchar(32) | ใกล้วันหมดอายุ / ถึงวันที่บันทึก / เลยวันที่บันทึก / บันทึกสูตรเข้าประวัติ / เพิ่มสูตรที่ชอบ |
| `event_key` | Varchar(200) | รหัสเหตุการณ์ ป้องกันสร้างซ้ำ เช่น วัตถุดิบเดียวกัน วันเดียวกัน และช่วงเดียวกัน |
| `target_type` | Varchar(16) | ประเภทปลายทาง: `ingredient`, `history`, `base_recipe` |
| `target_id` | Integer | รหัสปลายทาง ต้องมากกว่า 0; ตรวจสิทธิ์และการมีอยู่ของรายการอีกครั้งตอนเปิด |
| `payload` | JSONB | ชื่อ ณ เวลาสร้างแจ้งเตือน และวันหมดอายุ/ช่วงสำหรับแจ้งเตือนวัตถุดิบ |
| `created_at` | Timestamp with time zone | เวลาสร้าง ส่งผ่าน API เป็น UTC และแสดงตามเวลาไทย |
| `read_at` | Timestamp with time zone, nullable | เวลาอ่าน; `null` คือยังไม่อ่าน การปิด toast ไม่เปลี่ยนค่านี้ |
| `withdrawn_at` | Timestamp with time zone, nullable | เวลาถอนแจ้งเตือน เช่น หลังแก้วันหรือลบวัตถุดิบ ซ่อนจากรายการและยอดกระดิ่ง แต่เก็บแถวเดิม |

เพิ่มข้อกำหนดและดัชนี:

- `UNIQUE (user_id, event_key)` ป้องกันเหตุการณ์ซ้ำต่อบัญชี แม้มีคำขอพร้อมกัน
- `CHECK` จำกัดประเภทแจ้งเตือน 5 แบบ ประเภทปลายทาง 3 แบบ และ `target_id > 0`
- `ix_notifications_feed (user_id, withdrawn_at, read_at, id)` ช่วยค้นรายการแยกตามบัญชีและสถานะ
- `notifications_id_seq` จ่ายเลข ID ใหม่ และเปลี่ยน revision ใน `alembic_version` เป็น `b9c0d1e2f3a4`

Migration เพิ่มโครงสร้างเท่านั้น ไม่สร้างประวัติแจ้งเตือนย้อนหลังหรือเพิ่มคอลัมน์ให้ตารางเดิม ผลตรวจหลัง migrate ยืนยันว่าเนื้อหาและโครงสร้างของ 15 ตารางแอปเดิม รวมถึงสถานะ 14 sequence เดิมไม่เปลี่ยน [รายละเอียดผล migration](notifications-migration-result-2026-10-15.md)

การแสดงรูปใช้ `image` ที่มีอยู่แล้วในข้อมูลวัตถุดิบ จับคู่กับ `target_id` ฝั่ง frontend จึงไม่เพิ่มรูปลง `payload` หรือเพิ่ม schema ใหม่ เมื่อไม่มีรูป รูปเป็น placeholder หรือโหลดไม่สำเร็จจะแสดงไอคอนเดิม รูปเป็นรูปปัจจุบันของวัตถุดิบ ไม่ใช่ภาพย้อนหลัง ณ วันแจ้งเตือน; toast หลายรายการใช้กระดิ่ง ส่วนชิ้นเดียวใช้รูปได้

Schema ท้องถิ่นตรวจแล้ว แต่ยังไม่ได้ทดสอบด้วยบัญชีจริงข้ามอุปกรณ์ Backup อยู่ดิสก์เดียวกันและยังไม่ได้ทดลอง restore
